# AgriShield API Endpoint Documentation

This document outlines all public and internal REST/HTTP endpoints provided by the **AgriShield** web application.

---

## 1. General & Health Endpoints

### `GET /health`
- **Description**: Lightweight health check endpoint for monitoring, load balancers, and CI sanity checks.
- **Authentication**: None required.
- **Response Format**: `application/json`
- **Sample Response**:
  ```json
  {
    "status": "ok",
    "service": "AgriShield Crop Observation & Escalation App",
    "version": "1.0.0"
  }
  ```
- **Status Codes**: `200 OK`

---

## 2. Farmer Observation & Scan Endpoints

### `GET /`
- **Description**: Displays the home page with quick action buttons, language toggle, and system metrics overview.
- **Authentication**: None.

### `GET /observe`
- **Description**: Renders the multi-step Farmer Observation Form.
- **Supported Crops**: Tomato, Potato, Rice, Maize, Chili, Grape, Apple.
- **Authentication**: None.

### `POST /observe`
- **Description**: Submits a full farmer disease observation report including image and field metadata.
- **Form Data Parameters**:
  - `farmer_name` (string, required)
  - `farmer_contact` (string, optional)
  - `crop` (string, required) - Choice of supported crops
  - `growth_stage` (string, required) - e.g., Vegetative, Flowering, Fruiting, Harvest
  - `region` (string, required) - Region/District name
  - `first_symptom_days` (int, required) - Days since symptoms first noticed
  - `symptoms` (array of strings, optional) - Selected symptom tags
  - `notes` (string, optional) - Additional contextual notes
  - `image` (file, required) - Image file (.jpg, .png, .jpeg)
- **Response**: Redirects to observation detail page `/observation/<id>` or renders form error.
- **Status Codes**: `302 Found`, `400 Bad Request`

### `GET /scan`
- **Description**: Quick scan camera interface for immediate single-photo prediction.
- **Authentication**: None.

### `POST /scan`
- **Description**: Rapid automated crop photo scanning with image quality check & ML prediction.
- **Form Data Parameters**:
  - `crop` (string, required)
  - `image` (file, required)
- **Response**: Renders instant scan result view with explainability breakdown.

---

## 3. Observation Tracking & Details

### `GET /observation/<int:id>`
- **Description**: Displays comprehensive details for a submitted observation including ML prediction, confidence level, escalation status, and expert feedback.
- **Authentication**: Public view for farmers/procurement managers.

### `GET /observations`
- **Description**: Lists all observations with filtering by status (`pending`, `escalated`, `reviewed`, `resolved`), crop, and region.
- **Query Parameters**:
  - `status` (string, optional)
  - `crop` (string, optional)
  - `search` (string, optional)

---

## 4. Expert Escalation Dashboard

### `GET /expert/dashboard`
- **Description**: Main dashboard for agricultural experts and quality control officers to review escalated crop disease cases.
- **Authentication**: Required (Role: Expert / Admin).

### `POST /expert/review/<int:observation_id>`
- **Description**: Submits expert feedback, diagnostic verification, action recommendations, and quality impact ratings for an observation.
- **Form Data Parameters**:
  - `expert_diagnosis` (string, required) - Expert confirmed diagnosis
  - `expert_confidence` (float, required) - Expert confidence score (0.0 - 1.0)
  - `recommended_action` (string, required) - Immediate advisory or treatment
  - `procurement_action` (string, required) - `ACCEPT`, `REJECT`, `QUARANTINE`, or `PRICE_DISCOUNT`
  - `review_notes` (string, optional)
- **Response**: Updates database record status to `reviewed`/`resolved` and redirects to expert dashboard.

---

## 5. Analytics & Outbreak Detection

### `GET /analytics`
- **Description**: Renders interactive analytics charts for disease prevalence, regional heatmaps, escalation resolution latency, and procurement impact.

### `GET /outbreak-alerts`
- **Description**: Displays active real-time regional outbreak alerts generated by spatial-temporal clustering algorithm (>= 3 cases of same crop/disease in same region within 48h).

---

## 6. Procurement & Batch QA

### `GET /batch-qa`
- **Description**: Quality Assurance dashboard for food-processing unit batch intake decisions.

### `POST /batch-qa/evaluate`
- **Description**: Evaluates crop batch quality metrics based on disease prevalence in supply region and determines batch lot acceptance risk.

---

## 7. Authentication Endpoints

### `GET /login` / `POST /login`
- **Description**: User login for experts, procurement managers, and administrators.

### `GET /logout`
- **Description**: User session logout.

---

## 8. Error Response Formats

All non-HTML API/web errors return user-friendly custom views (`404.html`, `500.html`) without exposing raw traceback strings or database secrets.
